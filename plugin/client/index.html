Guest Portal

Create one rich guest link for the TREK plan and optional Journey photos.

Guest portal setup

v1.0.4 security model: The anonymous portal runs in the hardened companion container, normally reverse-proxied at /guest-portal/. Share tokens stay in the guest-link fragment and are exchanged once for an HttpOnly guest session; subsequent API URLs contain no bearer tokens.
Use /guest-portal/ when the companion container is reverse-proxied under the same TREK hostname. This is recommended because the portal can call TREK's public APIs same-origin.
The native TREK share remains the authority for trip access. The guest portal itself shows only Plan, Flights, Reservations and Photos.

Your guest link

The TREK/Journey share tokens are kept in the URL fragment after #. The browser sends them once in a JSON POST body to establish a Secure, HttpOnly guest session; they are never placed in API request URLs. Anyone who has the original guest URL has the same read-only access as the underlying TREK share links.

Revocation: delete/regenerate the normal TREK share link (and Journey share if used). Because the portal intentionally reuses those public permissions, the plugin does not pretend to provide a separate revocation boundary.
