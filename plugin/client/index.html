Guest Portal

Create one rich guest link for the TREK plan and optional Journey photos.

Guest portal setup

v2.0.3 security model: The anonymous portal runs in the hardened companion container, preferably on a dedicated guest hostname. Share tokens stay in the guest-link fragment and are exchanged once for an HttpOnly guest session; subsequent API URLs contain no bearer tokens.
For normal browser use, a dedicated guest origin such as https://guest.example.com/ is recommended. TREK is a PWA and a TREK Service Worker on the main application origin can intercept same-origin guest navigation in browsers that already use TREK. A same-origin path such as /guest-portal/ remains supported when that is not a concern.
The native TREK share remains the authority for trip access. The guest portal itself shows only Plan, Flights, Reservations and Photos.

Your guest link

The TREK/Journey share tokens are kept in the URL fragment after #. The browser sends them once in a JSON POST body to establish a Secure, HttpOnly guest session; they are never placed in API request URLs. Anyone who has the original guest URL has the same read-only access as the underlying TREK share links.

Same TREK origin detected: this link can be intercepted by TREK's PWA Service Worker in a browser that already uses TREK. For the most reliable guest behavior in the same browser, configure a separate guest hostname that reverse-proxies directly to the companion.
Revocation: delete/regenerate the normal TREK share link (and Journey share if used). Because the portal intentionally reuses those public permissions, the plugin does not pretend to provide a separate revocation boundary.
